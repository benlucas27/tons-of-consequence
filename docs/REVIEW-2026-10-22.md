# Security, data and bug review (22 Oct 2026)

## Fixed in this change (branch review-fixes)
- Added browser protection headers on every page: X-Content-Type-Options, X-Frame-Options (same site only), Referrer-Policy, Permissions-Policy (microphone only for our own voice search). Checked locally on pages, the service worker and card images.
- Added /.well-known/security.txt (contact ben@haveaplan.xyz).

## Found, needs a decision
1. **Next.js 14.2.35 has open advisories (npm audit: 1 critical, 2 high).** Most need features this site does not use (image optimiser, server actions, rewrites, Pages-Router i18n, custom servers, CSP nonces), and the site is on Vercel, which patches some at the platform level. The real fix is a major upgrade (Next 15/16 plus React 19), which is a project of its own: do it on a branch with a full visual check. Until then the exposure is mainly request-based denial of service on server-rendered pages.
2. **Card image routes (/card/...) are open and cost CPU (about 1.3 s each).** Each distinct URL is generated once then cached, but anyone can ask for thousands of different combinations (for example /card/compare?a=1&b=N). Suggest a Vercel Firewall rate limit on /card/* and /mcp (Ben, in the Vercel dashboard: Project > Firewall > Rate Limit). Bad inputs are handled safely today (400/404 for invalid ids, odd query values ignored).
3. **No Content-Security-Policy.** Needs testing with the inline scripts, YouTube embeds and Vercel Analytics. Start with Content-Security-Policy-Report-Only.
4. **/mcp and /api/feed allow any origin (CORS *).** Intended (public, read-only data, no sign-in); no private data is exposed.
5. **Rediff source links use http://** (88 in press-references.js, 1 in verdict-sources.js). https works, so these can be switched; left alone because they are data files.
